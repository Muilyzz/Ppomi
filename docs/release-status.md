# Ppomi 0.1.0 출시 점검

2026-09-06 로컬 저장소와 GitHub 릴리스 확인 기준. `backlog.md`는 9월 3일 자산관리 중심의 이전 계획이며, 현재 출시 상태는 이 문서를 먼저 참고한다.

## 클릭 중 포커스·창 순서 보완

단일 창 전환 후에도 사용자가 클릭할 때 미러링이 움찔한다고 보고했다. 이전 실행 확인은 클릭이 끝난 뒤의 좌표를 비교한 것이므로, 클릭 순간의 포커스나 창 순서 변화가 없었다는 증거로 간주하지 않는다.

작업대의 SwiftUI·보고서 웹 뷰·배경·승인 버튼은 클릭의 자동 창 올리기를 미루고 해당 마우스 동작에서 취소하도록 수정했다. 다른 앱을 사용 중일 때 일반 탐색이 뽀미의 키보드 포커스를 자동으로 요구하지 않도록 했으며, 뽀미를 직접 활성화하거나 입력 필드를 사용하는 경로는 유지한다. Stage Manager가 미러링의 실제 창을 잠시 보고하지 못할 때는 기존 연결을 0.5초간 유지해 즉시 숨김·재표시하는 것을 피한다.

전체 Swift 테스트 94개가 통과했고 같은 개발 서명 요구사항을 유지한 수정본을 설치했다. 잠금 해제 후 화면 제어 도구의 좌표 클릭으로 보고서 본문·절차·타임라인을 비교했다. 수정 전에는 뽀미가 미러링 위로 올라가는 상태가 두 차례(표본 간 약 9ms·66ms) 관측됐으며, 수정 후 같은 클릭 순서에서는 관측되지 않았다. 두 빌드 모두 클릭 구간의 폰 좌표는 일정했고, 수정 후 탭 전환 및 창 올리기 지연 콜백 적용을 확인했다.

이 비교에는 화면 제어 도구의 앱 활성화·준비 클릭이 섞여 있다. 수정 후에도 도구가 이미 뽀미를 활성화한 상태에서 웹 뷰가 키 포커스를 얻었고, 다른 창이 두 앱 사이로 들어올 때 순서를 보정하는 동작은 남아 있다. 따라서 일반 사용자 클릭에서 움찔 현상이 완전히 사라졌다고 판정하지 않는다. 창 순서는 약 120Hz로 샘플링했으므로 더 짧은 변화는 놓칠 수 있다. 플레이북 카드 상세 확인은 화면 제어 연결 오류로 완료하지 못했다.

`PPOMI_WINDOW_TRACE=1`로 실행하면 로컬 표준 오류에 클릭·키 포커스·창 순서·좌표 변화를 기록할 수 있다. 기록은 기본적으로 꺼져 있으며, 창 제목·화면 내용·입력 문자열은 포함하지 않는다. 로컬 측정 로그는 공개 저장소에 넣지 않는다.

## 단일 배경 창으로 변경

2026-09-06 키오스크와 일반 창을 미러링 바로 뒤에 놓이는 하나의 `MainPanel`로 통합했다. 같은 일반 창 레벨 안에서 앞뒤 순서를 유지하며, 키오스크 전환은 현재 화면의 사용 가능한 영역(`visibleFrame`)으로 같은 창을 확대한다. 별도 Space나 네 개의 `.screenSaver` 패널을 만들지 않고, 전역 제스처 차단과 반복적인 포커스 고정을 제거했다.

초록 버튼·`⌃⌘F`로 전환하고, 확대 중에는 **창으로 돌아가기**도 사용할 수 있다. Dock 아이콘으로 다시 열면 같은 창과 현재 모드를 유지한다. 사람이 미러링 창을 직접 옮겼을 때는 폰을 원래 위치로 되돌리지 않고 뽀미 배경 또는 옆 열 배치가 따라간다. 상태 안내와 사람 승인 버튼은 폰 옆 열 하단에 두어 키가 큰 폰 아래로 숨지 않게 했다.

변경 후 확인한 결과:

- `swift test --package-path Ppomi`: 전체 87개 통과, 실패 0.
- 이전과 같은 Apple Development 서명 요구사항을 유지한 빌드로 설치·재시작했고, 손쉬운 사용·화면 기록 권한이 유지됐다.
- 실제 설치 앱에서 초록 버튼으로 같은 “뽀미” 작업대 창이 확대되고 **창으로 돌아가기**가 표시되는 것을 확인했다. 확대 상태에서 타임라인·절차 탭을 전환해도 미러링 위치가 유지됐으며, 복귀 버튼으로 일반 창의 원래 도킹 위치로 돌아왔다.
- 폰은 `IN_USE` 상태였으므로 폰 앱 안의 작업이나 결제는 실행하지 않았다. 수동 폰 이동을 따라가는 배치 계산은 회귀 테스트로 확인했다. 화면 제어 도구의 드래그로 실제 창이 이동하지 않아 직접 드래그 추종은 실행 검증하지 못했고, Space 전환도 실행 검증하지 않았다.

아래의 기존 테스트와 설치 앱 검증 기록은 이 변경 이전의 결과다.

## 개발 서명 전환 후 권한 복구

2026-09-06 애드혹 빌드를 Apple Development 서명으로 교체한 뒤, 시스템 설정에서 허용 표시가 있어도 앱의 손쉬운 사용·화면 기록 검사가 실패했다. `tccd` 로그는 현재 앱을 `com.muilyzz.ppomi`로 정확히 식별하면서, 저장된 애드혹 `cdhash` 조건과 새 개발 서명 요구사항이 일치하지 않아 거부한다고 명시했다. 같은 표시 이름의 옛 앱도 설치돼 있었지만 이번 거부의 확인된 원인은 남아 있던 서명 조건이다.

현재 앱의 `Accessibility`와 `ScreenCapture` 권한만 `tccutil`로 초기화하고 `/Applications/뽀미.app`을 정확히 재등록했다. 사용자 인증·허용 후 앱을 재실행하자 권한 없음 안내가 사라지고 실제 폰 상태인 “손에 든 iPhone · 잠그면 돌아옴”이 표시됐다. 기존 앱과 다른 앱의 권한은 변경하지 않았다. 이어서 일반 창의 타임라인·절차 탭을 바꾸어도 미러링 창 위치가 유지됐으며, `⌃⌘F`로 키오스크의 중앙 배치와 일반 창의 원래 도킹 위치로 복귀하는 것을 실제 화면에서 확인했다.

이후 로컬 설치는 같은 앱 식별자·설치 경로·개발 인증서를 유지한다. 키오스크의 초록 버튼은 별도로 마우스 이벤트만 가로채던 경로를 실제 버튼 동작으로 바꿔, 접근성 도구의 누르기도 같은 키오스크 전환을 수행하도록 수정했다. 최종 설치본의 서명 요구사항이 이전 개발 서명과 같음을 확인한 뒤 교체·재실행했으며, 권한은 유지됐다. 실제 설치 앱에서 초록 버튼을 접근성 도구로 눌러 키오스크 전환과 미러링 창의 중앙 배치를 확인했고, `⌃⌘F`로 일반 창 도킹 상태에 복귀했다.

가져오기로 저장된 검증용 패키지를 로컬 카탈로그에 다시 두고 앱 재시작 없이 새로고침하자, 기존 5개 카드에 데이터가 정의한 여섯 번째 “데이터 연결 확인” 카드와 작업 설명이 표시됐다. 검증 후 테스트 패키지는 실제 카탈로그 밖으로 정리했다. 카드 상세 화면은 화면 제어 도구의 연결 오류로 검증하지 못했으며, 이 결과에 포함하지 않는다.

## 실폰 재생 검증 절차

1. 폰을 잠가 Mac 옆에 두고 `phone state`가 CONNECTED인지 확인한다. 로그인과 인증은 사람이 한다.
2. MCP에서 `read_playbook`으로 대상 앱의 절차와 공통 규칙을 읽는다. 현재 날짜에 유효한 비결제 탐색 흐름을 사용하고 이전 예약 조건을 그대로 실행하지 않는다.
3. `run_combo`에 대상 `app`과 `max_steps: 1`을 전달한다. `phone_screen`으로 실제 화면과 반환 결과를 대조한다.
4. 아는 길이 없으면 그 결과를 기록한다. 비결제 탐색을 한 단계씩 수행해 발자국을 만든 후 같은 시작 화면에서 재생을 확인한다.
5. 정상 경로, 낯선 화면 정지, 사용자 차례 정지를 각각 확인한다. 결제 지점은 자동 탭 없이 멈추는지만 확인하며 이 검증에서 결제 승인을 요청하거나 결제하지 않는다.
6. 각 실행의 시각·앱·걸음 수·정지 이유·기대 결과 일치 여부를 기록한다. 화면 증거는 로컬에만 보관하고 개인정보·예약번호·금액은 공개 문서나 발자국에 옮기지 않는다.
7. 성공한 비결제 경로로 20초 데모를 만든다. 공개 전 화면의 개인정보 노출 여부를 확인한다.

## 출시를 위해 남은 입력과 작업

- Developer ID Application 인증서와 공증용 Issuer ID 확보 후 서명·공증·staple 검증.
- 공증 성공한 ZIP으로 릴리스 파일 교체, 프리릴리스 해제, 다운로드 링크와 안내 변경.
- Lemon Squeezy 상품과 결제 URL 확보 후 랜딩 연결.
- 실폰 재생 검증과 데모 완료 후 홍보 진행.

푸시와 배포 시 개인정보 파일 및 private-history 브랜치는 포함하지 않는다. 배포는 기존 hub/ Vercel 프로젝트를 사용한다.
