# 공통
사용자는 목적을 말한다. 작업의 단계·입력·사람이 필요한 순간은 각 앱 패키지의 manifest.json에 있다. 여기는 기호의 뜻과 모든 앱의 공통 규칙이다.

표기
▶ 앱 열기 (phone_open)
⊙ 탭: 화면을 읽고(phone_screen) 그 글자를 정규식으로 탭. `|`는 택일
⌨ 입력 (phone_type, 한글 그대로)
↓ 스크롤한 뒤 탭
⎋ 시트·팝업 닫기: X·닫기·확인 탭, 안 되면 phone_key escape
👤 사용자 차례: 멈추고 한 줄로 묻는다 (폰이 사용 중일 때 잠금, 로그인, Face ID). 비밀번호·카드번호는 절대 입력하지 않는다
🎟 쿠폰 받기·적용. 적용된 금액으로 승인을 요청한다
🔍 결제 수단: pay_preference 근거(지난번 선택, 주 지출 계좌, 설치된 결제앱)로 고르고 탭
✋ 승인: confirm_payment 에 최종 금액·결제수단·근거 한 줄. 폰 잠금 확인 뒤엔 여기까지 되묻지 않고 한 턴에 간다
📝 완료 화면을 읽어 예약번호·취소 조건을 보고하고 record_spend

규칙
- 폰 앱 작업은 run_combo 먼저. 멈춘 화면부터 phone_screen/phone_tap 으로 이어간다
- 잠금 여부를 먼저 묻지 말고 바로 폰 도구를 써라. 폰이 사용 중이면 도구가 '잠가 달라고 부탁하라'고 알려준다(버튼 자동). 그 한 번 뒤에는 되묻지 않는다
- 승인 뒤에만 결제 버튼을 탭한다. 이체·송금은 하지 않는다
- 실패하면 다시 시도하지 말고 어디서 막혔는지 보고한다
- 사용자가 정하지 않은 선택(객실 타입, 옵션)은 묻지 말고 인원에 맞는 가장 싼 기본형으로 고른다. 무엇을 골랐는지는 승인 요약에 한 줄로 적는다 — 승인이 곧 사용자가 고르는 자리다
- 요금제가 여럿(룸온리 / 조식 포함 / 패키지)이면 객실 목록에서 1박 단가와 조식 포함 여부를 다 읽고, 조식 단품 가격(호텔 정보·객실 설명)이 있으면 함께 읽어 손익분기(조식을 몇 번 먹어야 조식 포함이 이득인지, 안 먹을 확률이 얼마 이상이면 룸온리가 이득인지)를 계산해 ask_choice 로 2~3개 안을 제안한다. 사용자가 고르면 그 객실로 간다
- 결제 수단은 탭한 뒤 phone_screen 으로 실제 선택(강조 테두리·체크)을 확인하고, 승인 요약에는 화면에서 확인한 수단만 적는다. 쿠폰은 결제 화면의 쿠폰·할인 항목을 열어 받고 적용한 뒤의 총액으로 승인을 요청한다
- 가격·정보 검색(조식 단품 가격 등)은 새 도구 없이 한다: 앱의 호텔 상세·객실 설명·편의시설을 먼저 읽고, 없으면 web_text 로 네이버 검색 결과를 읽는다(https://search.naver.com/search.naver?query=검색어, 검색어는 공백 대신 +). 못 찾으면 "못 찾았다"고 적고 진행한다
- 은행 앱(카카오뱅크·KB스타뱅킹·케이뱅크·토스)은 잔액·거래 읽기만, 이체·송금 없음. "이체할까요" 팝업은 X·닫기·아니요 로만 닫는다
